# UMURAVA delivery roadmap

| Sprint | Scope | Exit evidence |
|---|---|---|
| 01 | Repository foundation, database, web and mobile shells | Reproducible builds and baseline smoke tests |
| 02 | Authentication, scoped RBAC, sessions, audit | Security tests and threat-model review |
| 03 | Local-first outbox, pull/push sync, checkpoints and conflict handling | Disconnect/reconnect, duplicate and crash-recovery tests |
| 04 | Community, Rwanda geography and resource catalogue | Tenant-isolation and integrity tests |
| 05 | Energy, water and food workflows | Ledger correctness and reconciliation tests |
| 06 | Health availability and transport workflows | Privacy review and workflow tests |
| 07 | Emergency incidents and communications | Delivery, escalation and recovery tests |
| 08 | Forecasting, allocation recommendations and route optimization | Baselines, model evaluation and human override |
| 09 | Sector/district/national reporting | Aggregation validation and access-control tests |
| 10 | Edge installation, cloud deployment, backups and observability | Restore drills and edge isolation tests |
| 11 | Load, penetration, resilience and field pilot | Signed production acceptance report |

Sprints are engineering increments, not a promise that all work can be safely completed in a single unattended change. Hardware integration, field trials, legal review and independent security testing are release dependencies.
